## 一、为什么收窄

原稿提出“没有东西能回答真实模型的改动效果”，并推荐先设计完整 headless 任务的通用评测器。
到本次开工时，这个前提已过期：plan 204、209、216、220 已有专项真实模型实测记录，当前缺的
是可复用的实验口径，不是首次证明 A/B 有价值。

其中 plan 220 的记录直接说明观察边界的重要性：恢复长会话，在出事位置只采下一条回复，
能判断模型是否选择正确等待工具；它不执行这些工具，不能据此证明真实后台作业的收尾或
端到端耗时正确。完整任务验收仍有价值，但不能把所有问题都塞进同一种执行器。

本次只读这些已有记录来确定方法来源，没有重新核验本机原始捕获，也没有开展新的真实实验。

## 二、用户已定的形式与范围

- **通用规则**：仓库内 `rust/DESIGN.md`「Behavior evals」节，一份供人和 agent 执行、核对的
  Markdown 规范；不会自动加载、调度或强制执行。
- **每次实验**：在对应 plan 的「实测协议」中，跑前填具体口径，跑后补计数、协议偏离、结论
  与限制。DESIGN 提供可复制的记录模板，不规定运行时 JSON schema。
- **原始证据**：请求、回复、会话、生成代码和凭据只留本机私有目录；仓库仅放不含敏感内容的
  方法、汇总与结论。真实 API 的代理、key 和预算由每次任务另向用户确认。
- **门禁**：真实模型行为评测不进 `make check`。本次只改文档，按仓库规则运行提交门禁，
  不追加 `make check-release`；门禁通过不是协议效果已经由新实验验证。

原稿的运行环境、用例、模型预算、评分和首次 A/B 五个开工问题不再适用于本次：本次不执行
实验。这些值由未来具体实验跑前填写，不在通用协议里预选。

## 三、定稿的决定

1. **分清观察范围**：触发点重放与完整任务验收各自声明边界。只采首轮选择不声称后续执行
   正确，重建夹具不冒充完整事发快照。
2. **控制变量并核对生效**：固定输入、恢复状态、模型与 rail、参数、提示、工具和环境，
   记录两臂版本及唯一被测因素。模型输入改动核对实际请求；纯执行层改动核对实际路径。
3. **跑前定口径**：主指标、副作用检查、样本清单和数量、交替顺序、并发、超时/轮次、重试、
   预算与停止规则先写清。不规定统一题数或每臂三次，也不让中途结果改变正式样本口径。
4. **探索与确认分开**：变更输入、评分或处理后另记一轮，不能把开发中成功的样本混入正式结果。
5. **保留完整计数**：技术失败、缺失、重复、不可评分单列，不静默剔除或补样成成功，不冒充
   模型低分。分母和失败处理预先声明，配对结果说明覆盖，缺遥测不是零。
6. **结论跟着证据走**：优先用工具调用、文件、测试和状态判定，防止“失败归零”其实是功能
   消失；小样本的零失败不构成保证，零差值或未显著不等于效果相同。
7. **承认隔离与自动化边界**：本机独立 HOME/工作区不是密封隔离；协议本身不检查请求、
   调度样本或统计结果。自动化等重复需求明确后再提取，不预选实现语言或容器方案。

细则和模板只在 DESIGN 维护，本节记录定稿理由与范围，不另存一份会漂移的完整协议。

## 四、方法来源与保留的教训

- Pi 的方法来源保留在 `refs/README.md`：预先列计划、交替顺序、核对完整配对、承认遥测缺失。
  只借方法，不引入 vitest-evals，也不照搬“任一 blocked 就扣住整集通过率”的框架报告政策。
- `204-started-is-not-the-same-as-finished.md`：同一中断现场可用来对比恢复措辞，不必每次重新造现场。
- `209-compact-with-a-focus.md`：目标问题不再出现时，还须确认摘要该有的内容没有一起消失。
- `216-no-means-stop-and-listen.md`：除了该触发规则的情形，也要有容易误触规则的对照。
- `220-the-wait-wording-needs-model-evidence.md`：预定正式样本、核对请求差异、保留技术失败，
  区分原始触发点、合成夹具及只观察首轮的证据边界。

原稿关于 request reduction 的提醒仍有价值：对照开关必须真的触发。若新 stub 只在缓存已冷时
落，连续 headless 任务未必产生两臂差异；不能拿一次未触发的 no-op 说明功能没有收益。
这条原则适用于模型输入变化；不要求纯执行层修复必须改变请求。

## 五、明确不做

- 不新增 `kloop-eval`、Rust crate、脚本、CLI 配置项或运行时埋点。
- 不固定产物 schema、协议 digest、断点续跑、通用题库、Docker 或模型矩阵。
- 不把 variant 限成“一份配置”；提示或工具描述的比较可能需要两个二进制。
- 不再以“Python 进不了门禁”作为选 Rust 的理由；如何接门禁由项目决定。
- 不运行真实 API、读取凭据、创建实验环境，或修改已有专项实验的计数和结论。
- 不承诺后续平台实现任务；重复需求出现后，再为明确的自动化工作另行立项。
