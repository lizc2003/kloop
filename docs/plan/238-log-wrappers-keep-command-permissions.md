# Plan 238 — 日志包装不该抹掉命令授权

> 来源：2026-10-23，用户截图反馈 `make check > /tmp/log 2>&1; echo "EXIT:$?" >> /tmp/log; tail ...`
> 只能逐字记在会话中，无法保存项目 permissions，反复等待与重跑代价过高。
> 用户同意按“命令前缀 + 日志写入范围”保存，不授权整个项目的所有复杂脚本。

## 实现范围

- Bash 分析显式保留固定输出重定向的路径，支持 `>` / `>>` / `>|` / `&>` / `&>>`；
  fd 复制与 `/dev/null` 继续按原流重定向处理。输入重定向、heredoc、赋值、命令替换仍 opaque。
- 只对 `echo` 参数中的 `$?` / `${?}` 识别退出码回显，不能进入命令名、重定向目标或其他命令的参数。
- 复合脚本的输出目标要求绝对路径；单命令允许相对目标。多命令相对目标涉及执行中 cwd，
  本轮不假设它等于工具初始 cwd，保留 opaque。文件范围授权限 Unix；Windows Git Bash
  路径尚未映射成原生路径，权限层仍按 opaque，不能拿错误坐标生成目录授权。
- 普通审批保存原命令前缀与独立 `bash_write(<目录 glob>)`；沙箱升级保存
  `sandbox_escalate(...)` 与 `sandbox_escalate_write(<目录 glob>)`。两种同意不互通。
  新路径规则只按规范目标匹配，防止原路径别名把目录授权带到目录之外。
- 新规则同时接通会话缓存、项目存储、重启后匹配，以及执行前的沙箱升级记忆；命中时不先失败重跑。
- 写入不能变成只读或可并发；deny / explicit ask、危险命令、敏感路径和 Plan gate 保持优先。
  目录含 glob 元字符时不生成扩大授权范围的模式；新写入规则保留目录名的前导空白。

## 验收

- 截图同形脚本可提供 Project 并落盘；新会话换测试参数、日志名和 tail 行数后仍命中。
- 换命令或日志目录、增加未授权重定向时仍需审批；只有命令规则不能覆盖写入，反向亦然。
- 两条审批路径、会话粒度、规则隔离、符号链接目标、Plan / 并发 / deny / ask / 敏感写入均有回归。
- 用真实 shell 执行路径证明记住升级后跳过沙箱首跑。
- 更新 DESIGN 原权限段落与 HANDOFF；外层执行沙箱之外完整 `make check` 全绿后一次提交。
