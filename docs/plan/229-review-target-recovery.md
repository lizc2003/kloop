## 范围

- 复用当前会话中用户明确给同一个 PR 的目标分支，不重复询问，也不从当前
  分支、默认分支或 head ref 推断目标。只有用户消息可提供这项事实。
- 元数据失败后先核对 origin 与请求仓库，匹配才尝试已有 `gh api` 对同一
  完整元数据地址做一次只读查询；没有客户端、不匹配或仍无有效字段才交还。
  不扫描凭据，不添加地址猜测、候选分支遍历或新认证存储。
- 目标确定后直接进入已有固定版本准备阶段；同轮排队工具不能抢在准备前
  读取工作区。保持取消、权限、工具结果配对、恢复和补读预算。
- 不扩写 code-review skill，不给 web_fetch 加 Git 执行能力。

## 验证

增加用户事实来源和 PR 绑定、认证回退、无认证最终交还、排队工具隔离等回归。
以现有真实截图和入口失败记录确认提前交还；完整 `make check` 在外层执行沙箱之外运行。
同步改写 DESIGN 既有段落，记录实际能力边界，不把查询失败变成目标猜测。

## 真实验证协议（采样前固定）

沿用用户已授权的 provider / model、实际源仓库、PR 及已确认目标，新增一个
有界样本。新会话输入同时携带用户已确认的目标事实，不能把真实 Git 当前分支
当作证明。最多 12 次实际请求 / 12 轮 / 900 秒，重试计入、不补样；核对是否
无需目标提问即可进入固定差异阶段并报告。私有配置、捕获、报告只留临时目录，
不改实际仓库文件、分支、追踪 refs 或 FETCH_HEAD，不运行被审查项目的门禁。
无认证且没有用户目标的路径通过确定性回归验证，不声称该场景可自动得知目标。
