## 问题与实现

审查在访问失败后反复猜路径；拿到 head 后仍未确认实际目标分支；固定提交的 diff
与另一个工作区的查找混用；大段 diff 被截断后继续按完整覆盖推进。联网失败与成功
诊断拼在一条 shell 中，还可能把失败退出码覆盖掉，影响执行器识别。

- PR 先用已有认证 CLI / API 或 Git remote 定位。PR ref 仅能证明 head，不能据此
  推断目标分支；已有元数据无法确认时才询问缺失目标。只 fetch 所缺对象或 ref。
- 匿名 404、DNS 失败与敏感路径拒绝分别处理，停止无依据的 URL / IP / 凭据探测。
  联网命令独立保留退出码，超时使用 Bash 工具已有参数。
- 固定 PR head、目标分支 tip、merge-base；单提交固定 revision 与 parent。
  搜索和正文使用 `git grep` / `git show` 读取指定 SHA；工作区文件须包含本地修改
  一并核对一致，才能作为同版本证据。
- 先取完整文件清单，独立读取同轮提交；逐文件、逐 hunk 记录覆盖，截断后补读。
- 扩展现有关键契约测试，同步 DESIGN 原有 builtin review 段落与 HANDOFF。

- **证据边界**：两臂的请求和工具历史自然分叉，缓存、远端元数据与 DNS 不可冻结，

## 固定 PR 预处理与原生交还

第四轮的四次回复仍全部继续定位，两臂各两次均未直接澄清。累计 60 次实际请求
保留原身份。撤回未证明有效的系统段落，不再继续依靠加重提示词来保证停止。

模型激活内置 `code-review` 且参数包含一个支持的 PR URL 时，运行时先发起一次
固定元数据查询：支持 GitHub PR 及 Gitea / Forgejo 的 `/pulls/<number>` 入口，保留
自托管路径前缀。查询复用 `web_fetch` 的来源、hook、权限、超时和地址限制，不读取
凭据，也不绕过网络门。它目前使用已配置的 fetch 来源，不自动调用托管 CLI。

取得合法 head、实际目标分支与目标 tip 后，把固定字段交给 skill，后续仍须校验
本地 remote、计算 merge-base。查询失败或字段不足时，运行时直接记录并显示一个
缺失目标问题，配对工具结果，结束当前 turn，不请求模型再次选择动作。skill 作为
调度顺序边界；其后未开始的工具不执行，用户取消仍优先。用户提供目标后可沿已有
skill 正文继续；这一交还不是任务已经审查完毕。

此预处理仅限模型激活的内置 skill；无 PR 参数、单提交、工作区、用户覆盖 skill、
Program 桥接、slash 展开和未支持的托管入口不套用它。不匹配的入口仍按原有指令执行，不声称
执行器已经约束所有审查路径。版本读取与覆盖契约仍由模型遵循。
