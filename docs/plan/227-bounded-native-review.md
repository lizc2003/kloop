## 实现范围

- 原生交还同时记录可恢复状态；用户补齐一个明确目标分支后，在模型采样前校验
  origin 与 PR 身份，通过固定托管 ref 和新读取的远端目标 tip 冻结范围。
- Git 查询、缺失对象获取、merge-base、完整文件清单和逐文件差异均走已有 Bash
  门禁，不检出分支、不读取凭据、不绕过 hook、权限或沙箱。失败停止并明确交还。
- 最多准备 128 个文件、120,000 字符的差异；逐文件核对截断，超预算或不可读的
  文件记录缺口。台账证明差异是否准备完整，不代替模型实际审查和 finding 判断。
- 正文阶段仅提供固定版本的结构化读取 / 搜索入口，底层仍为受门禁约束的 Bash；
  不提供自由 Bash、网页、委派或写操作。最多 16 个补查调用，耗尽后只请求报告。
  显式轮次上限的最后一轮预留给报告；不增加外层采样预算。收尾仍要求真实模型
  生成结论，原生只补范围、准备缺口和补查失败事实，不能合成 finding 或宣告无缺陷。
- 状态与准备材料随会话持久化；压缩保留当前原生状态和材料。取消、拒绝、任务
  切换、用户覆盖 skill、Program / slash 和非 PR 入口保持各自边界。
- 用户续问后补充通用 `web_fetch` HTTP 失败指引：保留错误状态与 URL，区分认证、
  拒绝、匿名 404 的不确定性、资源移除、限流与常见服务错误。错误正文不当页面
  内容，不自动重试或绕过访问限制；DNS / 传输 / 地址限制仍保留原始错误来源。
