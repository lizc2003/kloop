## 继续修复：把等待约束放进 harness 消息

用户看到上述结果后要求「要想办法解决啊」。系统提示本来就把工具输出视为数据；
继续向启动回执堆指令并不能保证模型采纳。新方案保留原工具说明和回执，在轮次边界把
当前活跃后台 Bash 的 ID 与等待规则作为独立 `Injected::Harness` 消息追加到历史尾部。
它与其他 harness 提醒使用同样的 `<system-reminder>` 形状，不混进 tool result，
也不改动系统提示的缓存前缀。

提醒明确覆盖“作业把结果写到另一个日志”这一场景：先用该 ID 的阻塞 `bash_output`
等待结束，再读实际日志；仍可继续无依赖工作。ID 清单来自原生注册表，只列活跃作业，
顺序稳定；同一清单不重复追加，作业结束后不产生新提醒。压缩或 rebase 后清空去重状态，
下一轮按活跃注册表重新注入。没有拦截或改写合法脚本中的 `sleep`。

先做了独立的 10 次探索采样：仅在 B 请求尾部增加这条 harness 提醒，9 次首选正确阻塞的
`bash_output`，1 次直接读取当前日志，固定 `sleep` 为 0/10，无技术失败。
这 10 次只用于开发，不合并进正式结果。

正式确认预先固定为 **30 次 B（`4d49ba0`）+ 30 次 C（新增原生 harness 提醒）**，
重新采样两组，交替 B/C 与 C/B，最大并发仍为 4。原始截断位置、系统提示、模型、代理、
输出上限、工具清单与原生请求投影保持一致；先核对请求差异只有新增的最后一条提醒。
正式结果不因探索或中途观察而增减样本，不按有利结果补算成功。

这个回归断言，并重新做行为实测；字面相等仍不能证明模型会采纳措辞。

两条 agent 集成测试的后台夹具改为明确取消前持续运行，末尾使用原生注册表 shutdown。
它们不再靠 `sleep 30` 保证检查时仍在运行，因此机器负载不会因作业自然到期而让清单或
子 agent 可读性断言假红。

### 有用作业对照协议

另行固定 **30 次 S（空等待）+ 30 次 P（有产出的监测）**，不复用旧批次作对照，交替
S/P 与 P/S，最大并发 4。使用同一授权配置、模型、路由、系统提示、工具清单与原生请求
适配器，仍只采首轮回复、不执行生成的工具，技术失败保留原分母、不补样。

两组都沿用原始截断前缀加两个独立作业的结构，目标是 `bg-12`，提醒示例是 `bg-10`；
同样保留“另外两条独立作业继续运行”的用户说明。各自的启动后都加一次非阻塞
`bash_output` 快照：S 是空输出的长等待；P 是源码和文档文件清单的持续监测，用于后续审查。
两个监测进程实际生成了非空清单文件与更新输出，冻结这份快照后已停止；模型请求中的
ID、启动回执与状态消息仍是合成重放夹具，不是假称模型实际启动或查询了它们。

预采样请求逐字段核对：两组均为 569 个 input items，差异仅有两个启动调用的 arguments
（命令与用途说明）和两个状态快照的 output，共四处。系统、目标命令、用户说明和整条
原生 harness 提醒完全一致。不能将新 S 与旧批次直接作因果比较，因为新两组都增加了
状态快照；本次比较的是**作业用途、命令与可见产出这一整组夹具形状**，不能继续拆解成
某一个单独字段的作用，也不能把它推广到所有模型或多作业会话。

### 有用作业对照结果

60 个实际请求逐一与各自预采样请求核对，全部一致；两组各 30 次按计划完成。

| 观察项 | S：空等待（30 次） | P：有用监测（30 次） |
|---|---:|---:|
| 第一条调用为目标 `bg-12` 的阻塞 `bash_output` | 18 | 27 |
| 第一条调用为停止独立作业的 `stop_bash` | 12 | 1 |
| 同条回复包含目标的阻塞 `bash_output` | 26 | 27 |
| 正常回复仅停止独立作业、没有等待目标 | 4 | 1 |
| 同条回复等待错误 ID | 0 | 0 |
| 同条回复使用固定 `sleep` | 0 | 0 |
| 技术失败 | 0 | 2 |

P 的两次技术失败分别为服务端流错误（提示限流 429）和 HTTP 504；没有完整工具调用，
均保留在 30 次分母中，没有重试或补样。阻塞包含原生默认的 `block=true`，两组没有
非阻塞等待。比较首选正确阻塞等待 18/30 与 27/30，Fisher 双侧 `p≈0.0153`。

本次对照支持“独立作业夹具形状会影响首选动作”这个解释：提醒完全不变时，停止独立
作业的正常回复从 12 次变成 1 次。它不证明原来每一次停止都是合理的资源清理，也没有
分清命令、用途说明与可见产出各自的作用。P 仍有一次停止有用作业的回复，不能写成
“模型已经不会停止独立作业”。原先把停止行为直接称为模型偏航的表述已改写，旧样本
和计数全部保留；本轮也不与旧批次合并，不推导未经测试的其他模型、路由或会话行为。

两个实际监测进程已结束，所有临时配置副本已删除；源配置未修改，原始捕获只留在本机。
