# Plan 239 — Bash 结构化事实与字面输入误拦

> 2026-10-23。来源：临时 Rust 工程的 glob 匹配探针在带引号的 heredoc 中包含
> `<home>/.ssh/id_rsa` 测试字符串，被整条命令原文扫描判成敏感读取，执行前硬拒绝。
> 用户要求结合参考实现，制定语法分析与权限判断的实施计划。
> 状态：待实现。本次只提交计划；计划提交号以本文件创建提交为准，实现提交待补。

## 目标与已定取舍

让 Bash 分析同时回答两个问题：哪些完整事实足以授权，哪些局部事实足以拒绝或要求确认。
字面输入里的路径字符串不自动等于文件读取；脚本的未知部分也不能让已知危险和写入消失。

保留 tree-sitter-bash，复用现有参数角色表、路径规范化、权限次序与 macOS 沙箱。
新增内部事实表示，首批修复带引号的 heredoc 写入测试源码这一场景。
不更换解析库，不增加模型分类器，不实现 Bash 解释器、通用符号执行或跨语言数据流分析。

本计划的安全取舍已定：

- **完整分析才可形成前缀/路径范围授权；局部分析只补拒绝、风险与未知事实。** heredoc 本轮仍不生成
  命令前缀或项目持久授权，也不变成只读、可并发调用。
- **收窄原文扫描必须有执行保护。** 首批只在实际执行的 macOS 沙箱已覆盖相关凭据根时，
  才豁免确定是字面输入的正文片段。没有保护、覆盖不明或实际脱沙箱时保留原保守判断。
- **不靠操作系统读取失败再自动脱沙箱兜底。** 本次依赖凭据隔离才能获准的调用，在
  自动升级、记住升级、bypass 和主动 `disable_sandbox` 路径都不得丢掉这个前提。
- Linux/Windows 尚无对应沙箱实现，本轮保留原行为；不把跨平台沙箱建设塞入本任务。
  首批之外的字面输入误报可以继续保守拒绝，不能宣称所有“提到敏感路径”的误报都已解决。

## 现状与参考结论

当前 `rust/crates/core/src/shell.rs` 只给出 `Commands` / `WithWrites` / `Opaque`。
未认可的节点让整条脚本失去 argv 和写入事实；`permissions/facts.rs` 又先做整条原文的
敏感 needle 扫描。因此，heredoc 中仅用于字符串比较的凭据路径也会触发硬拒绝。

Plan 238 刚补齐固定输出的普通授权和升级授权，必须保留其“命令范围 + 输出范围”契约。
`tools/bash.rs` 的已记住升级会跳过沙箱首跑，失败后的升级也直接重跑；单改权限门中的
初次判定，会让新的正文豁免在第二条执行路径失去保护。

可吸收的参考形状：

- Codex 将完整命令分解与复杂脚本中的危险字面命令提取分开；后者明确不能用于证明安全。
  公开来源：`refs/codex/codex-rs/shell-command/src/bash.rs:129`，
  `refs/codex/codex-rs/shell-command/src/command_safety/is_dangerous_command.rs:50`。
- 其他参考把参数、重定向和字面输入分开处理，未知参数保留位置，路径检查与命令规则分别判定。
  它们不静态证明任意 Python/Rust 程序的全部文件访问；执行隔离承担这部分边界。

以上是设计结论，不复制参考产品的提示词、工具定义、运行捕获或不可公开的实现坐标。

## 一、一次解析，两种用途的事实

在现有 shell 模块内增加小型事实结构；具体类型名由实现决定，不增加第二套权限引擎。
同一棵语法树同时产生原有严格分析和风险证据，避免各调用方重新扫描或自行拆分 shell。
可保留 `analyze_bash` 门面供现有调用者使用。

事实至少保留：

| 事实 | 必需信息 | 用途 |
|---|---|---|
| 命令 | 可执行词、按位置保留的字面/未知参数、原文范围 | 参数角色、deny、危险判断 |
| 重定向 | 方向、fd、目标的字面/未知状态、原文范围 | 读取与写入不能藏进 argv |
| 字面输入 | 正文范围、分隔符是否引用、消费命令、所属语法结构 | 区分数据与 shell 代码 |
| 上下文 | 组合/管道/替换关系、cwd 是否仍可确定 | 判断输入去向与相对路径 |
| 完整性 | 哪些结构未理解、是否解析出错或超限 | 限制事实可用于哪种决定 |

- 未知参数不能删掉后再让角色表处理剩余 argv；未知值保留位置，无法确定参数个数或
  角色时退回保守检查，不猜后续 token 的含义。
- 第一轮不追踪 `cd` 后的实际 cwd。受影响的相对路径标为未知；绝对路径仍可独立检查。
- 对 `bash`/`sh`/`zsh -c` 等已支持的脚本包裹复用有界递归；超限、动态命令名与不认识的
  wrapper 选项都产生未知事实，不据此授权。
- 语法错误、缺失节点、遍历/递归超限时不豁免正文，也不恢复任何自动授权。
  局部风险扫描若不能可信定位，回退现有整条命令处理。
- 不展开变量、glob 或命令替换，不执行命令来“算出”参数，不引入跨调用解析缓存。

## 二、风险判断接入局部证据，授权保留严格分析

`permissions/facts.rs` 消费上述事实；`argv_roles.rs` 继续维护命令各参数的角色。
不把每个调用者各自的字符串扫描变成新的语义来源。

- 已知命令、读取目标和固定输出即使与未知结构同处一条脚本，也继续参与 deny、
  敏感读取与危险判断。动态部分存在不能抹掉另一段明确的 `cat ~/.ssh/id_rsa` 或危险删除。
- 部分命令证据仅用于拒绝/要求确认；不能通过把未知参数删掉，命中更窄的 allow 前缀。
  deny 匹配需要明确区分完整命令前缀与局部风险证据，不能把重排/缺失后的 argv 当原命令。
- 已识别的输出写入保留危险类别检查；未知输出/输入效果使脚本继续不能按只读放行或并发。
- 严格分析成功的调用继续走现有 `Commands` / `WithWrites` 授权、记忆与升级规则。
  现有只读元数据豁免、参数角色表和 Plan 238 路径范围保持。
- heredoc 所在调用本轮仍按 opaque 处理授权：普通批准只可按现有规则逐字记住会话同意；
  局部命令事实不能生成 Project 规则、shell 写入范围或升级前缀记忆。
- 敏感读取硬拒绝仍在 Plan / bypass / 沙箱自动放行之前；正文被证明是数据时，才不再
  把相应文本当作读取证据。未知与已确认读取使用不同内部状态，不混用错误解释。

## 三、只认可边界明确的字面 heredoc

首批候选限于独立的 `cat` 写固定文件：命令为明确认可的 `cat` 可执行形式，无文件参数，
标准输入来自一个完整的带引号 heredoc，标准输出写入固定字面路径。
多个这样的写入可通过已识别的顺序/条件连接组成原形脚本；每段分别核验。
可支持完整的单引号、双引号或反斜杠引用分隔符及 `<<-`，但必须按真实语法树与原文
核对边界；实现不能可靠支持的变体回退，不用正则猜一个更大的正文范围。

以下不获正文豁免：

- 未引用的 heredoc、here-string，以及不完整/无法识别的分隔符。
- 直接向 shell、Python、Node、`eval`、`source` 或未知命令提供正文。
- 候选处于管道、命令替换、进程替换或未知复合结构中，无法证明 stdin/stdout 的去向。
- 同一命令多个 heredoc、非标准 fd、fd 覆盖顺序、附加重定向等超出已建模范围的写法。
  不能只看命令名称和最后一个目标就忽略之前实际发生的重定向。

正文的“字面”仅说明 shell 不展开它；不承诺生成的程序稍后运行安全。原场景中后续
`cargo run` 仍可能执行任意代码，因此是否减少原文敏感匹配，还必须经过下一节的保护核验。

原文扫描只跳过已认可的正文范围，执行始终使用完整原文。正文外的命令、输出目标、
同一行放在 heredoc 开头后面的管道/命令等继续检查；不能把整个 `heredoc_redirect`
节点当作可删文本，节点可能同时容纳会执行的兄弟结构。

首批路径覆盖也收窄：只对能可靠识别为已保护根内的 home 相对拼写或绝对路径取消
原文敏感命中；例如 `~/.ssh/id_rsa` 与实际 home 下对应的绝对路径。正文含相对目录、
其他用户路径、未知拼写或保护范围外的另一处敏感 needle 时，保留原拒绝。
覆盖判断必须检查每一处命中，处理规范路径、符号链接和 `..`；无法证明覆盖就回退。
不为识别 Rust/Python 字符串写一个新的语言解析器，也不做全局字符串替换。

## 四、执行保护与脱沙箱复核

### 4.1 复用现有沙箱的凭据根保护

CLI 构建沙箱时，在现有私有状态目录保护之外，把当前用户 home 下的 `.ssh`、`.aws`、
`.gnupg` 同时加入读拒绝和写拒绝。拒写用于防止先移出禁区再读取；保留原文与规范路径，
包括根目录自身是符号链接时的目标。无需枚举或读取真实凭据内容。

- 复用 `SandboxPolicy` 的路径规则与 macOS Seatbelt 生成器，不新增可由模型覆盖的开关。
- 实际策略若被调用方替换、缺少相应拒绝、允许读取 carve-out 重新打开该范围、或无法
  确认生效，就不能作为正文豁免的依据；不能因“配置了 sandbox”就假定凭据已受保护。
- 已有 offload 读回与 worktree 例外维持；它们不应扩大到凭据根。
- 本轮不将 `.git`、所有 rc 文件和 `.env*` 全部改成 OS 读禁区，避免破坏 git 和 shell
  启动语义。这些类别继续走原有静态判定；首批豁免不依赖尚未实现的统一保护。

### 4.2 用明确执行上下文取代对 auto-allow 布尔值的猜测

权限门获得“本次执行是否保留所需读写拒绝”的内部上下文；它和 `trust_sandboxed`
是否免审批是两件事。关闭沙箱自动放行、但仍确实在受保护沙箱内运行时，也可消除误报，
只是继续按原 opaque 规则审批。

上下文只能由实际执行策略构造，不接受模型参数自报。依赖正文豁免的调用携带保护要求，
在启动子进程前核验同一份策略，不能初次判定后更换成无保护的执行方式。

必须覆盖同一条执行路径上的全部入口：

- 普通前景、背景 Bash。
- 主动 `disable_sandbox`、没有沙箱、平台不支持或沙箱启动失败。
- 沙箱失败后自动升级，包括 bypass 下免审批升级。
- 已记住升级导致的首跑前脱沙箱，包括会话通配升级记忆。
- scheduler 等直接调用前景 Bash 执行器的内部入口；不能只修工具派发入口。

依赖保护的调用不允许在上述路径丢掉保护后执行；先复核、后询问或启动，旧升级记忆
不覆盖新的保护要求。保护无法保留时返回明确的保守拒绝，不产生可批准绕过的选项，
也不附带建议脱沙箱的通用重试提示。未依赖本次豁免的既有调用继续沿用原升级行为。

## 五、实施顺序与改动落点

同一计划按以下顺序完成，中间步骤不单独放开误报豁免：

1. 先写原形探针的敏感门回归及拒绝边界；证明旧实现会把单纯路径样本误判。
   另写“复杂结构不能抹掉明确危险/敏感读取”的回归，分别确认当前缺口。
2. 在 `shell.rs` 及必要的同模块子文件实现共享解析事实；严格授权结论先保持原样。
   接通 `permissions/facts.rs`、`rule.rs` 的风险消费者，不让局部事实流入 allow/记忆。
3. 补 `sandbox/mod.rs` 与 CLI `startup.rs` 的凭据根保护，接通明确执行上下文和启动前
   复核。串起 `tools/mod.rs`、`tools/bash.rs`、背景和 scheduler 的实际启动路径。
4. 在上述保护成立后，接通有限的字面 heredoc 正文豁免，验证原形调用可继续运行。
   审批记忆与 Plan 238 的严格命令路径保持独立。
5. 更新 DESIGN 原权限、Bash 分析与沙箱升级段落，记录 HANDOFF；完成全门禁后一次实现提交。

如果现有大文件需要拆分，只沿 shell 事实或执行保护的职责拆；不借本任务重构整个权限模块。
复用当前拒绝/错误协议，优先改正文文案，不增加新的前端交互或持久配置格式。

## 六、验收矩阵

测试只用临时目录中的合成凭据与 sentinel，不读取用户真实 home、配置或历史会话。
原始会话、模型和 provider 信息不入库。

| 情形 | 预期 |
|---|---|
| 原形：多个 cat heredoc 写 Cargo.toml/main.rs，源码含受保护根内的路径样本，再执行本地程序 | 受保护执行时不再报敏感读取；调用仍非只读、非前缀持久授权 |
| 受保护执行但 `trust_sandboxed=false` | 通过敏感门，仍按 opaque 规则确认 |
| heredoc 正文包含 `$()`、反引号、分号、中文与换行，分隔符已引用 | 只是输入数据；不能被当作额外命令，也不能遮掉正文之外的命令 |
| 同一条脚本另有真实敏感读取、敏感输出或危险命令 | 相应硬拒绝或原 safety 确认仍生效 |
| heredoc 直接送解释器、未引用正文含命令替换、管道送 shell、多个重定向顺序不明 | 不获豁免；保持保守处理 |
| 参数中间有变量/未知词，后面跟读取选项或路径 | 参数位置不丢失；不能借错位跳过真实目标 |
| cd、wrapper、嵌套 -c、控制流混合已知读取/写入 | 已知风险保留；未知部分不获得 allow 或只读授权 |
| 解析错误、缺失节点、超出分析限额 | 无正文豁免、无新增自动授权 |
| 正文路径不在保护范围、存在未覆盖的另一处 needle | 保留原敏感拒绝 |
| 主动脱沙箱、记住升级、自动升级、无沙箱和不支持平台 | 不能使用只在受保护执行中成立的豁免 |
| Plan、并发批处理、会话记忆、项目持久化 | heredoc 写入仍被 Plan 拒绝，不并发，不产生前缀/项目规则 |
| Plan 238：日志目标、canonical allow、deny/ask 别名、前导空白目录、升级记忆 | 原回归全保留；严格分析的授权范围不变 |

测试分三层：

1. **解析事实**：整对象核对参数位置、正文/重定向范围、上下文和完整性，覆盖 heredoc
   开头同一行还含可执行节点、fd 顺序与分隔符变体；不能只断言“没有返回 opaque”。
2. **真实权限门**：manual / plan / bypass，沙箱自动放行开关，deny/ask、已有普通与升级
   记忆组合。明确区分“通过敏感门”与“整条命令免审批”。
3. **真实 macOS 子进程**：使用注入的临时 home/保护根，先运行只比较路径字符串的本地
   小程序，再运行尝试读取合成 sentinel 的程序。前者成功，后者不能把 sentinel 带回输出；
   生成文件后再执行同样受保护。分别验证前景、背景及升级路径，副作用计数证明没有无保护
   的第二次执行。用本地工具与现有夹具，无 API、无新 registry 依赖。

权限回归先红后绿；风险补强用例与误报修复用例分别记录，不能把旧实现已经通过的拒绝用例
当作修复证据。沙箱用例验证实际访问结果，不能只检查生成的 Seatbelt 字符串包含某个目录。
对不能在当前平台执行的矩阵明确标注，不能用 mock 结果代替平台实测。

## 七、成本与边界

- **工程成本：中等。** 核心是有限的结构化事实、两个用途的消费者和执行前复核，
  不是换 parser 或重写 shell。实现覆盖 core shell/permissions、Bash 执行与 CLI 沙箱构建；
  主要验证成本在升级与记忆的组合，不只是一条 heredoc 单测。
- **运行成本：** 复用一次语法树遍历和已有 OS 沙箱，无额外模型调用、网络请求或新增
  常驻进程。只对有敏感原文命中的候选正文做保护覆盖核验，不为每次调用扫描磁盘凭据树。
- **兼容成本：** heredoc 授权范围保持原样。新增凭据根读写拒绝会让此前在沙箱内可访问
  这些目录的命令失败，这是本次收窄静态扫描所需的保护；不读取或修改用户凭据内容。
- **明确限制：** 不保证识别任意程序的文件访问，不提供任意路径的动态信息流保护，
  不宣称静态门是完整的文件系统隔离。没有 OS 保护的场景本轮仍可能出现同类保守误报。
  未来若要进一步减少这类误报或支持其他平台，应另行建立相应执行保护与证据，不能直接
  扩大本次正文豁免。
