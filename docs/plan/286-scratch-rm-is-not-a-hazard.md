# Plan 286 — 只删临时目录的 `rm` 不再当危险命令 ✅

> 2026-11-19 立。来源：plan 283 第十三节后续候选第 2 条，用户同意按“`rm` 的目标全是 `/tmp`、`$TMPDIR`
> 下的字面路径时，不再当危险命令询问”来做。

## 一、为什么

plan 283 阶段 4 一周的落盘数据里，危险命令询问 16 次，全是带 `-f`/`-r` 的 `rm`，其中 13 次目标在
`/tmp` 或 `$TMPDIR` 下（日志文件、探针目录、测试夹具）。阶段 0 的基线也是这个形状（36 次里绝大多数是
`/tmp` 探针）。这类询问只能“允许一次”，每次都问。

`argv_is_dangerous` 判 `rm` 只看选项、不看目标。DESIGN 的入选标准是“损失不可逆，且 git 也找不回”；
临时目录里的探针和日志是一次性的，删掉也不算损失，用户每次都会点同意。

## 二、做法

危险判定改成：`rm` 带 `-f`/`-r` 仍算危险，**除非每个操作数都满足下面全部条件**：

1. 是字面值：不含未知片段（变量、命令替换），不含 glob 或花括号字符（`*?[{`）；
2. 是绝对路径（`cd` 之后的相对路径无法确定落点）；
3. 解析到真实路径（最近的已存在祖先规范化，再拼上还不存在的部分）后，**严格**落在规范化后的 `/tmp`
   或 `$TMPDIR` 之内，不能是这两个根本身；
4. 不在工作区内（工作区本身在临时目录里的情况）；
5. 不是敏感路径（`.env`、凭据名等）。

其它约束：

- 选项只认第一个操作数之前的；操作数后面再出现 `-` 开头的参数就不豁免（BSD 的 `rm` 会把它当成文件名）。
  `--` 之后全是操作数。
- 只豁免直接执行的 `rm`，以及去掉包装器（`timeout`、`env` 等）后看到的 `rm`；`sudo rm` 不豁免。
  xargs 改写、循环绑定这些带未知值的视图照旧算危险。
- 叶子是符号链接时，按它指向的位置判断（保守）；路径中间的符号链接指出临时目录的，也不豁免。
- 只在 Unix 上生效；其它平台照旧询问。

不覆盖（本次接受）：`"$TMPDIR/…"` 这种变量写法（解析器只展开 `$HOME`），`cd /tmp && rm -rf x` 这种
相对路径。按 plan 283 阶段 4 的数据，13 次里能覆盖 10 次。工作区里被 gitignore 的临时产物不在本计划内。

## 三、验收

- 字面临时路径的 `rm -f`/`rm -rf` 不再产生 `destructive`；manual 下 `rm -f /tmp/x.log && cargo test`
  不问危险命令。
- 下面这些仍然是 `destructive`：临时根本身（`/tmp`、`/tmp/`、`/private/tmp`、`$TMPDIR` 的值）、glob、
  `..` 逃出、混入非临时目标、相对路径、操作数后跟选项、`sudo rm`、变量路径、xargs、指出临时目录的
  符号链接、工作区在临时目录里时删工作区内的路径。
- DESIGN 的危险命令一段写明这个例外。

## 四、结果（2026-11-19）

- `CallFacts` 记下工作目录；危险判定收成一个方法：直接执行的 argv 与剥掉包装器后的各个视图，凡是
  `argv_is_dangerous` 的，再看是不是“只清理临时目录的 `rm`”，是就不算。命令里任何一个词是
  `sudo`/`doas` 时不豁免（`sudo -u root rm …` 的原始 argv 认不出 `rm`，只有剥掉包装器的视图认得出）。
- 临时根是 `/tmp` 与 `$TMPDIR` 的规范路径；`$TMPDIR` 是 `/`、家目录或其祖先时剔除。操作数用已有的
  `PathFacts`（逐分量规范化，断链与缺失部分里的 `..` 解析失败）判断落点。
- 原来一条用 `rm -rf /tmp/x` 断言“安全检查压过沙箱自动放行”的用例改成 `rm -rf build`，意图不变。
- **回放**（plan 283 的回放工具，同一窗口 41 个根会话）：改动前 44 次询问、其中危险命令 17 次；改动后
  34 次、危险命令 7 次。剩下的 7 次：`"$TMPDIR/…"` 变量写法 3 次、工作区里的临时产物 2 次、
  `cd /tmp && rm -rf <相对路径>` 1 次、工作区外用户配置目录里的文件 1 次。变量写法和相对路径是第二节写明
  不覆盖的；后两类不在临时目录里，本来就该问。
- **验证**：新增 5 个用例（`plan286_*`）；kloop-core 库测试在执行器沙箱外跑了两遍：第一遍 1459 过、8 败，
  失败在 `shell_env`、`tools::fs` 的取消时序和 `tools::subagent` 的 worktree 用例，单独重跑这三组都过；
  第二遍 1467 全过（1 ignored）。`cargo fmt --check` 与 `cargo clippy -p kloop-core --all-targets
  -D warnings` 干净。没跑 `make check`。
