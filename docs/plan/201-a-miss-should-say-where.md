> 这是第 1 条。出处见 `refs/README.md`「chord 固定源码调研(2026-09-23)」。

## 一、为什么

`edit_file` 匹配失败时,kloop 只说一句
`edit_file: old_string not found in <path>{note}`(`core/src/tools/fs.rs:1151`,`note` 只在
文件自上次读后变过时才有内容)。模型不知道差在哪一个字符,通常的反应是整段重读、凭记忆重打
`old_string` 再试——一次失败至少多花一轮,重打本身又会引入新的漂移。

失败的两大来源,chord 各有一招(`internal/tools/replace_edit.go:203-313`、
`internal/tools/edit_helpers.go`):

1. **模型复述不出文件里的标点**:弯引号写成直引号、`—` 写成 `-`、中文全角标点写成半角,
   或者分隔符后的空格多一个少一个。内容完全对,只是字符不对。
2. **真的漂了**:少一行、多一个空格、文件已经被改过。这时最有用的是"文件里最像的那一段在
   第几行、哪几行不一样"。

## 二、形状

`apply_text_edit`(`core/src/text_edit.rs:24`)现在是两层:原样匹配 → LF/CRLF 回退。加两件事:

### 2.1 第三层:标点/空白容错匹配(只在唯一命中时生效)

原样和换行回退都是 0 命中时,把文件与 `old_string` 都过一遍折叠后再找:

- **逐字符折叠**(照 chord `normalizeProsePunctuationRune`,`edit_helpers.go:86-130`):
  `“ ” „ ‟` → `"`;`‘ ’ ‚ ‛` → `'`;`– — −` → `-`;全角 `,;:。.!?()` → 对应半角。
- **分隔符后单个排版空格可省**:`,` `;` `:` `.` `!` `?` `(` `)` 之后紧跟的一个空格视为可有可无。
  **引号与连字符不在内**——`" foo"` 与 `"foo"`、`- foo`(列表项)的空格有意义。
- **不折叠其他空白**:缩进、行内多个空格原样比较。缩进错是真错,不是排版差异。

**只在折叠后恰好命中一处时生效**(`replace_all` 时可以多处)。命中多处且没设 `replace_all` →
照现有措辞报"matches N times",并注明是容错匹配下的计数。

**写回时保留文件原有字节**:`old_string` 与 `new_string` 共有的前缀和后缀部分,用文件里的原字节;
只有真正被改的中间段用 `new_string` 的字符。否则一次只想改一个变量名的编辑,会顺手把整段
弯引号改成直引号——那是模型没打算做的改动。chord 的实现见 `punctuationTolerantEdit`。

成功结果照实说:`edited <path> (1 replacement, punctuation/whitespace-tolerant match at line N)`。

**工具描述不提这层容错。** 这是 chord 刻意的取舍(它的 `docs/edit-tools.md:243`),kloop 照做:
写进描述,模型就会把"差不多"当成目标,容错就从兜底变成了常态。描述里现有那句 CRLF 回退
保持原样——那条是在说文件的换行风格不会被动,是给模型的承诺,不是容错。

### 2.2 全部失败时:给出最近匹配块

三层都 0 命中时,在文件里按 `old_string` 的行数开窗,找折叠后最相似的一段:

- 相似度 ≥ 0.6 才展示(`minEditSuggestionSimilarity`,`edit_helpers.go:747`);低于它说明
  目标根本不在这儿,一个似是而非的"最近匹配"比没有更糟,退回通用提示。
- 展示:起始行号、相似度、**至多 3 行**不同之处(`maxDiffLinesShown`)——每行给出
  `file line N: …` 与 `your line M: …`,并点出第一个不同字符的位置。
- 行数对不上时说清楚:"你的 old_string 多出 X 行 / 文件多出 Y 行",全是空行时单独说明。
- **漂得太多**(不同的行 > 3,或整行漂移)时,**不再列差异**,直接给
  `call read_file with offset=<起始行> limit=<old_string 行数>`,并说"不要凭记忆重打这一段"。
  这与现有 `unread_edit_hint`(`fs.rs:1332`)给坐标的做法一致。
- 上限:`old_string` 超过 2000 字符、或文件超过 10000 行时不做相似度搜索(照 chord 的
  `maxEditSuggestionRunes` / `maxEditSuggestionLines`),直接给通用提示。

通用提示(没有足够近的匹配时)也改写成可执行的一句:目标可能已变或差得太多,重读那一小段、
用新读到的原文重建 `old_string`,不要原样重试。

## 三、不做

- chord 的**零宽字符/孤立变体选择符清理**(`replace_edit.go:152-186`):kloop 目前没有这类失败
  的实际记录,先不做;真出现了再加,那是独立的一层。
- chord 的"**原样重发失败的 patch 直接拒绝**":kloop 没有 `apply_patch`,而 `edit_file` 原样重发
  必然得到同一个确定性的失败——新的诊断信息已经足够让模型不去重发。
- 不改 `write_file` / `notebook_edit`。

## 四、开工时必须问用户的点(只有一个)

**容错匹配命中后,是直接写入,还是只报告"找到了一处标点不同的近似匹配"让模型确认?**

- **直接写入(推荐)**:唯一命中 + 保留原字节,误改的空间很小;而"报告后让模型重发"等于把本来
  能省的那一轮又花掉了。chord 就是直接写。
- 只报告:最保守。代价是这类失败永远要两轮。

## 五、实现要点(开工时核)

- 折叠要带**位置映射**:折叠后的每个字符记住它在原文里的字符区间(chord 的 `punctSpan`),
  命中后才能换回原文的字节区间去替换。先在折叠视图里找,再映射回原文切片——不要在折叠后的
  文本上做替换再写回。
- 与现有换行回退的关系:容错层在 LF 逻辑视图上做(`logical_lf_view`),换回原文时沿用它现成的
  `raw_boundaries` 映射,CRLF 文件不被改换行风格。
- `TextEditOutcome` 加一个字段表明走了哪一层(原样 / 换行回退 / 标点容错),替掉现在的
  `used_newline_fallback: bool`——三态用枚举,别再加第二个 bool。
- 最近匹配搜索放进 `text_edit.rs` 作为纯函数,返回结构化结果;措辞在 `fs.rs` 拼。
  相似度用有界编辑距离(chord 的 `bandedEditDistance`),别对整个文件做无界 DP。
- `text_edit.rs` 现在 292 行,加完预计 600~800 行;若超出,把最近匹配单拆成
  `text_edit/closest.rs`。

## 六、测试

- 折叠表每一项各一条:弯/直引号、三种破折号、全/半角 CJK 标点、分隔符后空格有无。
- 引号后、连字符后的空格**不**折叠(`"- foo"` 与 `"-foo"` 不匹配)。
- 缩进差异不容错。
- 唯一命中 → 写入,且共有前后缀保留文件原字节(整文件逐字节断言)。
- 容错下命中两处、无 `replace_all` → 报错并注明容错计数;有 `replace_all` → 两处都改。
- CRLF 文件走容错层后换行风格不变。
- 最近匹配:一字之差 → 列出那一行与首个不同字符;多一个空行 → 说明空行数不同;
  漂移 > 3 行 → 给 offset/limit 而不列差异;相似度 < 0.6 → 通用提示;超长 old_string → 通用提示。
- 原样命中与换行回退的现有测试一个不改、全部仍过。
- 结果文案整对象断言。
