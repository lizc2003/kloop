# Plan 242 — 图片作为输入框里的行内占位

> 2026-10-27。来源：用户报 Ctrl+V 粘进来的图片删不掉(`db78ac8` 先补了“草稿开头
> Backspace 删最近一张”),随后给出 codex 的样子：图片是正文里的 `[Image #N]`，插在
> 光标处，能与文字混排、整块删除。
> 状态：✅ 已完成（2026-10-27）。提交号以本节所在提交为准。

## 已定取舍

- **图片是 composer 文档里的原子**，与粘贴占位同一套机制：插在光标处，显示
  `[Image #N]`;光标进不去，按词移动一步跨过，相邻 Backspace/Delete 整块删掉。
  去掉输入框上方的 `📎` 行，也去掉 `db78ac8` 的“开头 Backspace 删最近一张”。
- **编号按粘贴顺序递增，不复用、不重编**(2026-10-28 用户改定;原先照 codex 删后
  连续重编，删了一张其余号跟着变，用户核对不了删的是哪张):新图取这次输入用过的
  最大号 + 1;最大号记在草稿上，提交或清空后下一条输入从 #1 重新开始。
- **发送形状**:正文在前，`[Image #N]` 原样留在正文里;图片按占位在正文里出现的
  先后跟在后面，第 k 张对应正文里第 k 个占位(2026-10-28 用户定，原为按编号)。不在每张图前另加标签文本块——OpenAI chat 与 Responses
  适配器会把一条用户消息里的文本块拼成一段、图片统一放在最后，单独的标签块会被
  粘到正文末尾。`--image` 的图排在输入框图片之后，不打乱编号。
- **steer 带图(用户 2026-10-27 同意)**:运行中按 Enter,正文和其中的图片一起进入
  当前 turn。`InboxItem::Steer` 改为带 `text` 与 `images`,注入消息为框定文本在前、
  图片在后。服务端 `turn/steer` 当时仍只收文字(随后单独一次提交接上，见完成记录)。
- **历史**:↑ 翻历史时图片随草稿一起恢复(文档原样存进历史，图片数据用 `Arc` 共享)。
- **slash 命令**:命令只收文字;命令行里的图片不进命令，留在输入框作为下一条草稿，
  与改动前附件留在输入框的行为一致。
- **中断退回**:turn 在模型出任何东西之前被打断时，恢复提交时的草稿原样(含图片
  位置);对不上时退回为文字 + 末尾补图。
- **切到原子的编辑**:粘贴占位切开时展开成原文;图片没有文字形态，切开即删掉该图。
  标签放不到字素边界上时(极少见，如紧跟组合符),在缺边界的一侧补一个空格。
- 原子(图片与粘贴占位)在输入框里用青色显示，与正文区分。
- 转录回显与回放不变：正文一行(含 `[Image #N]`),每张图另起一行 `[image: …]`。

## 实现

- `protocol`:`ImageSource` 加 `Eq`。
- `core/inbox.rs`:`Steer { text, images }` + `InboxItem::steer(text)` 便捷构造;
  `into_user_message` 把图片接在框定文本之后。
- `tui/composer.rs`:原子载荷分粘贴/图片;图片编号作为文档不变量，删除与切开后
  重排;`attach_image` 插在光标处;`submit` 交出正文、按占位先后排好的图片与草稿快照;
  `submit_command` 给 slash 用;视图给原子着色。
- `tui/app.rs`/`lib.rs`/`render.rs`:去 `📎` 行;steer 走完整提交并带图;
  Enter 时记下草稿快照供退回;worker 让输入框图片排在 `--image` 之前。
