# Plan 224 — 压缩优化的真实 provider 续跑验证 ✅

> 2026-10-12。用户同意使用事发时的 provider 现有代理和 key；旧版、新版各一次，
> 每次最多一次压缩加六轮续跑，总上限 14 次真实请求。原始数据与凭据仅留本机私有目录。
> 实验与证据记录已完成；文件恢复减负已验证，续跑质量比较因夹具缺陷未通过验收。
> 本记录提交以本文件所在提交为准；被测功能实现提交为 `0d44009`。

## 实测协议（跑前固定）

- **问题与范围**：从真实次新会话的压缩边界重放，检查摘要是否保留授权与约束、文件
  恢复是否减少无关内容、续跑是否误判进度。观察到任务结束或六轮采样上限；触及上限
  记未完成，不称为完整任务验收。摘要生成与后续工具都实际执行。
- **control / treatment**：A 使用 `ee3df19` 的压缩模块；B 使用 `0d44009`。
  唯一被测因素是整次压缩补丁，包含行段恢复和截止点说明；本轮不拆分两项的独立贡献。
  续跑使用共同的 `0d44009` 引擎。同一私有实验二进制包含两版原生压缩模块，入口只负责
  选择版本、恢复历史、记录结果和调用共同引擎；传输记录不改变模型请求正文。
- **输入与恢复边界**：同一真实会话在 `compacted` 之前的 245 条记录、133 条消息，
  不新增用户提示。工作区从 `957c9f1` 加 `e1a0571` 的未提交差异重建，使五份文档已修改、
  尚待复核和提交。每臂开始时重建独立状态，使用相同的工作区绝对路径；A 结束后归档，
  B 从初始模板重建。路径映射一致。系统提示与项目约定从重建环境生成并固定共用，
  不声称恢复了事发时未持久化的系统提示、缓存、审批或临时后台状态。
- **环境与参数**：`benli-gpt / gpt-6.1-sol`，Responses rail，`xhigh`，配置窗口
  258,400，原生路由实际输出上限 65,536。使用原生工具清单、权限与沙箱
  构造；两臂同为 bypass，避免无人应答的审批成为干扰。独立工作区和私有状态目录
  用于隔离写入；本机 HOME、系统程序仍共享，不是密封环境。完成或超时后收尾后台作业。
- **指标与评分**：每臂为一个预定样本，主指标为观察范围内是否保留约束并正确续跑。
  依据真实摘要、工具调用、工具结果、最终 diff 与提交，不采用模型自述作为完成证据。
  必查：不实现 plan 211；保持计划待实现；纯文档不跑 `make check`；保留沙箱外测试约定；
  不重复已完成的编辑或索取已有批准；英文提交且改动范围仅为已授权文档。另记录恢复
  文件的范围、估算 token、真实 usage、采样轮次、重读与重复编辑。摘要末尾状态按
  被折叠段判定，续跑状态按保留尾部判定，避免把正确的历史状态误评分为错误。
- **样本与执行规则**：预定清单 `(original-boundary, A, 1)`、`(original-boundary, B, 1)`；
  顺序 A 后 B、并发 1。只有一对，无法做顺序平衡或稳定性推断。每臂最多七次向远端
  发出的请求，包含原生重试；总计最多十四次。每臂墙钟上限 1,800 秒，续跑最多六轮。
  不补样、不按中途结果改口径；技术失败保留身份和分母，并报告实际已发送请求。
  采样错误、超时、请求预算耗尽或完成即停。原生重试若消耗额度，会减少剩余续跑空间。
- **请求 / 路径核对**：正式请求前导出两版原生压缩计划与确定性文件恢复结果，确认折叠
  和保留边界一致、请求只在补丁对应的摘要指令处不同。正式采样记录实际 wire 请求；
  首次摘要请求与预定输入核对，续跑首轮核对 anchors、摘要边界、恢复文件与原始尾部。
  分支后工具选择导致的历史差异单独记录，不要求后续请求逐字相同。

## 预采样

预采样已确认两臂均折叠 119 条消息、保留 14 条原文；压缩请求只在最后的摘要指令不同。
固定原摘要进行确定性恢复时，A 恢复 HANDOFF 的 1–208 行，B 恢复最近实际读过的
1–30 行，并补回尾部尚未覆盖的其他文件行段。此项核对不消耗真实 API 请求。

原始请求、回复、会话、工具输出、二进制身份与本机证据索引只留私有实验目录。
确定性预采样不计为真实 provider 已验证。

### 执行器修正与新一轮协议

首次尝试两臂都在远端请求之前遇到原生路由校验失败，实际 API 请求 **0 次**。
原因是执行器复用了创建子路由的兼容入口，未保留现场切换后的 route revision。
失败的两臂、日志和未执行的摘要 / 续跑均保留，不能记为模型失败或有效 A/B。
修正执行器为直接调用保持冻结路由的原生 `compact_once`；被测模块与模型输入不变。
修正后另记一轮 A/B，各一个预定样本，不把前一轮失败补算成成功；两轮累计远端请求
上限仍为用户批准的 14 次。其余评分、顺序、超时与停止口径不变，修正后重新做预采样。

### 续跑夹具限制

A 的续跑暴露了重建遗漏：工作区虽检出 `957c9f1`，但共享克隆的 `main` 仍指向
实验时的最新提交，且对象库可读到后来已完成本任务的 `e1a0571`。A 因 detached HEAD
检查分支，随后从 Git 历史发现任务已经提交，偏离了现场应继续完成文档提交的情形。
这是执行器夹具缺陷，不能把这次未完成或额外编辑归因于旧版压缩。B 保持同一初始夹具，
不在两臂之间更换输入；本轮续跑只能记录实际行为，不能据此比较任务完成率。

已另备离线修正夹具：`main` 与 HEAD 均停在 `957c9f1`，浅取该提交、不使用对象库
alternates，确认无法读取 `e1a0571`，且初始五份文档的工作差异与本轮完全相同。
这些检查不消耗 API；修正夹具未用于本轮，也没有另起真实采样。

## 真实压缩结果

修正入口后，两臂均收到真实 provider 的 `response.completed`。正式 wire 核对通过：
压缩请求仅最后的摘要指令不同，其余消息与参数相同；首轮续跑除输入内容外的字段相同，
两臂 anchors 和原文尾部 14 条逐字相同。B 的持久化摘要带固定截止点说明，第 9 项标题也
限定为被摘要段结束时的进度，保持十一项契约。

| 指标 | A：旧版 | B：新版 |
|---|---:|---:|
| 摘要字符数（含运行时前缀） | 24,468 | 13,342 |
| 摘要消息估算 token | 7,036 | 7,132 |
| 恢复文件字符数（含标题） | 22,648 | 11,529 |
| 恢复文件消息估算 token | 10,535 | 4,114 |
| 替换后全部消息估算 token | 42,462 | 36,137 |
| 真实首轮续跑 `input_tokens` | 40,720 | 34,550 |
| 首轮续跑 cached input | 0 | 0 |

估算沿用 core 的 ASCII / 非 ASCII 计数方式，包括消息包装；不能当成 provider 的计费
token。两份摘要的语言和内容长度不同，因此字符数大幅减少不代表摘要 token 减少。
本对样本的恢复消息估算减少 **60.9%**，首轮真实输入减少 **15.2%**；可支持文件恢复
减负已在真实请求中生效，不能据此声称摘要更短、响应更快或续跑更可靠。

实际恢复范围：

- A：README 1–103、CLAUDE 1–2、HANDOFF 1–208、Makefile 1–125。
- B：README 1–91、CLAUDE 1–2、HANDOFF 1–30、DESIGN 4284–4305、Makefile 1–105。

两份摘要都保留了不实现 211、计划待实现、纯文档不跑全量门禁、测试须在外层沙箱之外、
一次英文提交及五份文档范围等约束。第 9 项描述尚待编辑门禁规则，与被折叠段截止点
一致；尾部已经包含这些编辑，不能把这段历史描述当成最新状态错误。

### Usage 与成本边界

只汇总本轮中继捕获的真实响应 usage，不把恢复会话中既有的历史 ledger 算入新成本。
`input_tokens` 包含 cached input，二者不能相加；output 包含 reasoning。

| 范围 | 可得 usage 的请求 / 实发 | input tokens | 其中 cached input | output tokens |
|---|---:|---:|---:|---:|
| A：压缩 + 全部续跑 | 7 / 7 | 540,716 | 268,032 | 17,153 |
| B：压缩 + 有最终 usage 的续跑 | 6 / 7 | 461,036 | 192,384 | 16,236 |

B 中断请求的最终 usage **不可得**，不是零，因此不能把上表当作两臂完整成本差。
后续请求有缓存且工具历史已经分叉，不能把它们的总 token 或耗时差归因于压缩补丁。
两个压缩请求及两个首轮续跑的 cached input 均为零；首轮输入量比较不含这次缺失。

## 结论与后续边界

真实 provider 已验证行段恢复、固定截止点说明和保留尾部进入实际请求；这对样本首轮
输入减少 15.2%，关键授权约束未在摘要中丢失。摘要 token 没有减少，未验证摘要瘦身。
只有一对、固定 A 后 B、重建系统环境，不能据此推断稳定性或两项改动的独立贡献。

续跑比较受未来 Git 历史可见和一次中途断流影响，不能宣布端到端通过或新版完成率更高。
后续若再测，应使用已离线核对的修正夹具，重新固定协议并另行取得 API 预算；本轮没有
超出批准额度追加复测。仓库只提交本计划和 HANDOFF 的结果说明；实验代码与原始证据均
未入仓，按纯文档规则核对引用、状态、完整差异以及暂存前后的 whitespace 检查。
