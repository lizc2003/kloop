# Plan 287 — 写入被拒落在工具缓存里时，提议整个缓存根 ✅

> 2026-11-19 立。来源：plan 283 第十三节后续候选第 5 条。用户在两种做法里选了“提议上移到缓存根”
> （另一种是把常见缓存默认设为可写，被否：沙箱里的代码就能不经询问往模块缓存里植入代码）。

## 一、为什么

plan 283 阶段 2b 的写目录询问，提议的是被拒路径的**父目录**。包管理器缓存的目录结构按包分开，父目录只
覆盖这一个包：Go 下载依赖时被拒的是 `<模块缓存>/cache/download/<模块>/@v/<版本>.tmp`，授权 `@v`
目录之后，下一个新依赖还要再问；解压到 `<模块缓存>/<模块>@<版本>` 又是另一个目录。阶段 4 的数据里
Go 的模块缓存和 telemetry 目录各问了一次，都是这个形状。

## 二、做法

被拒路径落在下面某个已知缓存根之内时，提议这个缓存根；其它情况照旧提议父目录。

| 工具 | 缓存根 |
|---|---|
| Go 模块 | `$GOMODCACHE`，否则 `$GOPATH` 第一项下的 `pkg/mod`，否则 `~/go/pkg/mod` |
| Go telemetry | 用户配置目录下的 `go/telemetry`（macOS 是 `~/Library/Application Support`，其它是 `$XDG_CONFIG_HOME` 或 `~/.config`） |
| npm | `$npm_config_cache`，否则 `~/.npm` |
| cargo | `$CARGO_HOME`（否则 `~/.cargo`）下的 `registry`、`git` |
| Maven | `~/.m2/repository` |
| Gradle | `$GRADLE_USER_HOME`（否则 `~/.gradle`）下的 `caches` |

- 环境变量取的是 kloop 自己的环境（bash 子进程继承它）；命令里临时设的值（`GOMODCACHE=/x go …`）看不到，
  那时退回父目录。只认绝对路径的值。
- 缓存根同样要过原来的检查（绝对、不是 `/` 和家目录、无 glob、不敏感、不在已有可写根或禁写路径里），
  另外不能是家目录的祖先；不过关就退回父目录，不扩大。
- 日志给的被拒路径是真实路径，缓存根按原拼写和规范化后的两种形式比较。
- 回放工具用同一个函数算提议，计数与生产一致。
- 不做：把缓存默认设为可写；外部 CLI 的家目录（`~/.<tool>/tmp` 之后又问 `~/.<tool>`）这类没有已知结构的
  目录。

## 三、验收

- 上表每一项：被拒路径在缓存根下时提议缓存根；环境变量覆盖默认位置时按环境变量。
- 不在任何缓存根下的路径照旧提议父目录；缓存根是家目录的祖先或通不过检查时退回父目录。
- DESIGN 写目录一段写明。

## 四、结果（2026-11-19）

- `permissions::proposed_write_dir(path, home, var)` 算提议：先在上表的缓存根里找包含被拒路径的那个
  （原拼写与规范化两种形式都比），能授权、且不是家目录的祖先就用它，否则用父目录。bash 的写入能力询问和
  回放工具都改用它，后面的检查（能否授权、策略是否已经决定、去重）不变。
- **回放**（同一窗口 41 个根会话）：34 次不变，其中写目录询问 6 次不变。窗口里 Go 的那个会话本来就分别
  问了 telemetry 和模块缓存各一次，只是现在提议的是 `go/telemetry` 和 `pkg/mod` 整个根；省下的是之后每个
  新依赖的询问，这个窗口里没有出现。
- **验证**：新增 3 个用例（`plan287_*`：上表默认位置、环境变量改位置、根太宽或通不过检查时退回父目录）；
  kloop-core 库测试在执行器沙箱外 1472 过、1 ignored；`cargo fmt --check` 与 `cargo clippy -p kloop-core
  --all-targets -D warnings` 干净。没有真实 seatbelt 的端到端用例：那要么读真实家目录与环境变量，要么改
  进程环境，都会让测试随机器变；接线只是 bash 把 `path.parent()` 换成这个函数。没跑 `make check`。

## 五、复审修正（2026-11-19）

两条，核实后都成立，已修正：

1. **家目录按原拼写比、缓存根按解析后的路径比**（P2）。`$HOME` 经符号链接指向真实家目录时，规范化后的缓存根
   即使就是真实家目录或其祖先，`home.starts_with(root)` 和 `dir != home` 也都放行，会把整个家目录提议成项目级
   可写目录。同一个缺口也在父目录提议里：日志报的是真实路径，被拒文件直接在家目录下时，父目录就是真实家目录。
   现在 `grantable_write_dir` 按原拼写和解析后两种形式拒绝家目录**及其祖先**（原来连 `/Users` 这类祖先也能
   被提议）。**打扰**：不变；只是不再把家目录这一级提议出去。
2. **缓存根授权可能解除不了触发它的拒绝**（P2）。原来先把被拒路径上提到缓存根，再只检查缓存根是否已被策略
   决定；缓存里某个子目录有显式禁写时，缓存根照样通过，用户记住一条缓存级授权，重跑仍撞上原来的拒绝，再被问
   是否整个脱沙箱。现在 `proposed_write_dir` 带上策略判断，先看原始落点：父目录不能授权或已被策略决定时什么
   都不提议（和 plan 287 之前一样走整个脱沙箱）；缓存根本身被决定时退回父目录。bash 与回放共用。**打扰**：
   减少一次白问。

新增用例：符号链接的家目录（缓存根与父目录两种情况）、原始落点已被决定、只有缓存根被决定；plan 283 的提议
用例补上“家目录的祖先不提议”。

## 六、第二轮复审修正（2026-11-19）

三条，核实后都成立，已修正：

1. **被拒的就是禁写目录本身时仍提议无效授权**（P2）。上一轮只对父目录调用策略判断；缓存下的 `locked` 被显式
   禁写、被拒的正是重命名 `locked` 时，父目录和缓存根都能通过，重跑仍被同一条规则拒绝。现在被拒路径本身也
   过一遍策略判断。上一轮用例覆盖的是 `locked/entry`，这次补上 `locked` 本身。
2. **只解析了家目录，候选目录的别名仍能混过去**（P2）。被拒路径用原拼写、缓存根按这个拼写命中时，一个指向
   家目录或其祖先（甚至 `/`）的链接能通过检查；授权时 `with_grants` 又会把候选目录的真实路径加进可写根。现在
   授权检查拆成两半：`nameable_dir`（能写成规则）和 `safe_to_grant`（原拼写和解析后的落点都要过：不是 `/`、
   不是家目录或其祖先、不碰敏感目录；解析失败不授权）。
3. **父目录名有方括号时跳过了有效的缓存根**（P3）。上一轮父目录不能授权就提前返回；`~/.npm` 下某级目录叫
   `chunk[1]` 时，父目录写不成规则，但 `~/.npm` 能覆盖这次写入。现在提前返回只看策略判断和 `safe_to_grant`，
   父目录只是写不成规则时仍去找缓存根，找不到才不提议。

**打扰**：第 1、2 条只在少见的配置下不再提议无效或过宽的授权；第 3 条让这种目录名不再落到整个脱沙箱。
新增用例：禁写目录本身、指向家目录与 `/` 的链接、方括号目录（缓存内与缓存外）。

## 七、第三轮复审修正（2026-11-19）

两条 P2，核实后都成立，已修正：

1. **记住的写授权会跟着目录后来指向的新位置走**。提议时检查的是缓存目录的真实落点，项目规则却只存路径，
   每次生效时 `with_grants` 都重新解析它；缓存迁走后原路径变成指向家目录的链接，旧授权就会不经确认把家目录
   加进可写根。现在每次使用时再做一遍 `safe_to_grant`（`usable_write_grant`）：进 `Verdict` 的授权、判断
   “已记住”时用的授权都先过滤。
2. **重命名受保护目录的祖先时仍提议无效授权**。Seatbelt 对禁写路径的每一级祖先、以及可写根内受保护子路径的
   祖先都加了 `file-write-unlink` 拒绝，`already_decides_writes` 只看可写根和禁写路径本身及其后代。现在这份
   祖先清单抽成 `rename_guards`，profile 与新的 `SandboxPolicy::guards_rename` 共用；被拒路径本身被改名保护
   固定住时什么都不提议。在它里面新建文件照旧可以提议（只判断被拒路径本身，不判断父目录和缓存根）。

**打扰**：第 1 条只在授权目录后来变成危险链接时多问一次；第 2 条去掉一次白问。新增用例：迁走后变成指向家目录
的授权（不进 `Verdict`、不算已记住）、受保护祖先被改名与在其中新建文件。profile 的整段比对用例确认抽函数后
输出不变。

## 八、第四轮复审修正（2026-11-19）

- 写能力询问展示并记住所选目录的物理路径。应用授权时检查该路径仍解析到自身，再把这条路径
  放进 profile。旧规则若存的是别名，下次需要该能力时会重新询问，用户可以确认真实目录。
- 系统日志保留每条被拒的写操作和对应路径。只有 `file-write-unlink` 会查询改名保护。
  已落盘的输出前缀照常供回放读取，回放从已有的操作与路径恢复这一条拒绝。
