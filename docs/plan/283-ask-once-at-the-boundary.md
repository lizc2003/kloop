# Plan 283 — 只在越界时问，同一种越界只问一次

> 2026-11-11 立。来源：用户截图（`cd …/rust && cargo test … | tail -20`，带 "no OS sandbox"
> 通告，每次都问），以及「询问这块，反复修改了很多次，能有一个彻底的方案吗」。
> 状态：待实现。方向待用户确认（见第七节），确认前不动代码。

## 一、这次为什么一直问

1. **模型主动脱沙箱**。截至 11-11 17 时，kloop 仓库当天会话共 76 次 bash，其中 14 次带
   `disable_sandbox: true`，全部是 `cargo test` 或包含它的命令，没有一次先在沙箱里试过。模型思考原文：
   "AGENTS says tests must run outside the agent's outer sandbox: use `disable_sandbox=true`"。
   根 `AGENTS.md`「测试运行环境」是写给外层执行器的，kloop 自己的模型读到后照做了；
   工具描述里的 "never preemptively" 没压过项目指令。同一会话的 `cargo check/clippy/fmt`
   在沙箱内运行，一次没问。
2. **已有规则管不到**。主动脱沙箱跳过第 8 层（沙箱自动放行），只认 `sandbox_escalate(...)`；
   项目里的 `bash(cargo test *)` 按设计不覆盖脱沙箱，也没有 `sandbox_escalate(cargo test *)`。
3. **"不再询问"只记原文**。`| tail -20` 的第二个词以 `-` 开头，`argv_prefix_is_unstable`
   让整条命令退成逐字记忆（"only this exact command text"），也就不给项目选项；测试名、
   `tail` 行数每次不同，所以永远命不中。即便手写了 `sandbox_escalate(cargo test *)`，
   `matches_escalation` 要求每一段（含 `cd`、`tail`）都命中，只读段不豁免，结果还是问。

**共同的根**：拿"这条命令的文本"推导"同一个意图"的键。真实命令每次都带这一次特有的东西

来回拨。另外，"越界"有三个入口：模型主动脱沙箱、被拒后升级、已记住的升级跳过沙箱。三个入口
记忆各不相同，门和执行还各判一次（plan 245、266）。

**数据**（本机最近 40 个会话，只统计已批准并重跑的）：被拒后升级重跑一共只有 1 次；越界几乎
全部来自模型主动脱沙箱：kloop 仓库当天 14/76；另一个项目做网络诊断，当天 31/49，第一次联网
失败之后每条多行脚本都带这个标志，按原文记，每条都新。那个项目的 `permissions.json` 里还存下了
一条无用规则 `sandbox_escalate(cd <项目目录> *)`。
**kloop 设计的主路径（被拒后升级）几乎没被走过，反复出问题的是模型主动越界加文本键这条旁路。**

## 三、目标与验收

用户 2026-11-11 定的原则：**保证安全的前提下，尽量不打扰用户。**用户随后补充了两点：
实际使用中用户不看弹窗就点同意；权限层总体上是"防君子不防小人"，不可能既不打扰又没有漏洞。

由此定权限层的定位：**防的是模型的失误和习惯性越界，不防恶意代码。**对恶意的防线只有不依赖
用户注意力的机制：沙箱本身、deny 规则、敏感路径硬拦截。弹窗不是安全机制，同一类事反复问
只会把用户训练成见框就点同意。判据：

1. 沙箱里能完成的事不问。危险命令和显式 ask 规则除外，它们防的正是失误（现状已如此，保持不变）。
2. 越界只在第一次问，之后同一类越界不再问：联网可以记到会话（所有命令），也可以按程序记到
   项目；写某个具体目录、完全脱沙箱跑某个命令前缀，都按项目记。
3. 让越界本身尽量少发生（原则 2、3），而不是靠反复询问去拦。

验收：

- 越界询问里不再出现"只记这条原文"和"本会话所有越界"两种选项。
- kloop 仓库日常开发（改代码、跑相关测试）零询问；网络诊断类会话最多问一次（联网）。
- 安全面不放松：deny、敏感读写硬拦截、plan 模式、危险命令、ask 规则、bypass 语义都不变。
- **用数据验收**，不再用截图验收：见第五节阶段 0 的回放工具。基线是最近 40 个会话，
  每个阶段都报告每会话询问次数，并按判据分类（有界、无界）。

## 四、设计

### 原则 1：越界按能力问，不按命令问

被沙箱拦下的只有三类：联网、写工作区外某个目录、必须完全脱离沙箱（嵌套沙箱、无法归类的
拒绝）。kloop 的沙箱策略本来就能表达前两类（网络开关、可写根列表），所以：

- **联网**（用户 2026-11-11 定：会话级可以全放开）：同意的是"本会话的 bash 可以访问任意外网
  主机，文件写仍受沙箱限制"，之后的命令都在**联网沙箱**里跑，不再按命令询问。提示里必须写明
  是外网（plan 127：本机有代理时，放开回环就等于放开外网）。
  另有项目一档（用户 2026-11-11 提出）：按**程序**记，如 `sandbox_network(curl)`、
  `sandbox_network(git)`，之后这个项目里调用这些程序的命令都在联网沙箱里跑，不再问。
  - 按程序名记，不按两词前缀：联网是 `curl`、`dig` 这类程序的本职，第二个词通常是选项或主机名
    （`curl -sS …`、`dig example.com`），按两词记会重蹈 `tail -20` 的覆辙。写仍受沙箱限制，
    所以不必像完全脱沙箱那样按两词收窄。
  - 匹配规则与 `sandbox_escalate` 相同：调用里每个有效果的段都要被某条联网规则覆盖（只读段与
    `cd` 不算），才整条在联网沙箱里跑。沙箱按进程生效，整条 shell 都会获得网络，所以不能只覆盖
    其中一段。
  - opaque 脚本（多行诊断脚本）分不出段，只能用会话级。
  按域名放行要自带代理（参考 `refs/codex/codex-rs/network-proxy`），不在本计划范围内。
- **写工作区外**（用户 2026-11-11 定：写不能全放开）：只能按具体目录放。从拒绝证据里取出路径，
  提议"可写 `<父目录>`"并入可写根；取不到路径就不生成这项授权，也不猜。不提供"任意写"这一档。
  目录是 `/`、家目录本身或含 glob 字符时不生成授权；敏感路径与 `.git/hooks` 等受保护子路径
  照旧拒绝，不能靠这条放开。
- **完全脱沙箱**：第一次问，选项只有"允许一次"和"本项目以后都允许"，后者按原则 4 的键记成
  `sandbox_escalate(cargo test *)` 这样的规则，之后不再问。不提供会话级：每个会话重问一遍
  不增加安全，只增加打扰。提示要写明后果："这个命令会在沙箱外运行本仓库的代码"。
  这类规则防不了恶意：模型改一下测试代码再跑 `cargo test`，就能在沙箱外执行任意代码，
  `make check`、`cargo install` 也是这个形状。这是"防君子"定位下接受的代价（第六节）。

这与 codex 的三档对应：`UseDefault` / `WithAdditionalPermissions`（留在沙箱内放宽网络或路径）/
`RequireEscalated`，见 `refs/codex/codex-rs/protocol/src/models.rs:65`。

### 原则 2：模型不能自己把调用推到沙箱外

模型给出的越界标志只表达请求，不跳过沙箱内那次尝试：

- 请求联网：已有联网同意就直接在联网沙箱里跑；没有就问一次，问的是能力，不是这条命令。
- 请求完全脱沙箱：项目里已有匹配的 `sandbox_escalate` 规则就直接在沙箱外跑，跳过沙箱内的尝试；
  否则先在沙箱里跑，失败输出里有拒绝迹象（含 Unclassified）才问。带了请求但看不到任何拒绝迹象
  时不问，而是告诉模型"这次失败看起来与沙箱无关"。不能用"带了请求且失败"作为证据：有的模型
  习惯给每条 `cargo test` 都带上请求，测试失败在开发中很常见，那样每次测试失败都会弹窗。
  代价是真被沙箱拦了却没有可识别文字时，模型只能告诉用户，由用户加规则。

参数名、是否保留 `disable_sandbox` 作兼容在开工时定。工具描述、`DENIAL_HINT`、
`ESCALATION_DECLINED` 的措辞同步更新。

### 原则 3：让完全脱沙箱几乎不出现

无界的那一类只能靠减少发生来减少打扰：

- **拒绝分得准**：现在靠输出里的关键字分类，分不出就是 Unclassified，只能走完全脱沙箱。
  macOS 的系统日志会记录沙箱拒绝事件，包括操作类型和路径。codex 的调试命令用 `log stream`
  抓这类事件，见 `refs/codex/codex-rs/cli/src/debug_sandbox/seatbelt.rs`。kloop 如果能在失败后
  取到对应进程的拒绝事件，就能把多数拒绝准确归到"联网"或"写某目录"，走有界的同意。
  可行性和开销（是否要权限、延迟多少、能否按进程过滤）在阶段 0 实测，不成立就保留关键字分类。
- **嵌套沙箱在 macOS 上做不到**（2026-11-11 本机 Darwin 25.4 实测）：外层是纯 `(allow default)` 时
  内层 `sandbox-exec` 能成功；外层只要有任何限制，哪怕只是 `(allow default)(deny network*)`，
  内层都会报 `sandbox_apply: Operation not permitted`。所以不能靠调整 kloop 的 profile 来允许嵌套。
- **kloop 自测不需要越界**：需要真实 seatbelt 的测试，在 `KLOOP_SANDBOX=seatbelt` 时自己跳过
  （`tools/bash.rs` 已经给沙箱内的子进程设了这个变量）。做法同 codex：`CODEX_SANDBOX=seatbelt`
  加 `skip_if_sandbox!`，见 `refs/codex/codex-rs/core/tests/common/lib.rs:592`。只加测试侧 helper，
  不改生产代码的 `availability()`。
- **完整检查不能静默降级**：`make check` / `make test` 的意义就是全量，嵌套时跳过真实沙箱测试
  就不再是完整检查。Makefile 给这两个目标设一个变量（名字开工定），有它时嵌套直接失败，并写明
  "需在沙箱外运行"，不跳过。这样 `make check` 在沙箱里一定失败，触发出沙箱询问，按原则 1
  第三条按项目记住（用户项目里已有 `sandbox_escalate(make check *)`，修好键之后直接命中，
  不再问）；跳过只留给针对性的 `cargo test`。
- 改写 `AGENTS.md`「测试运行环境」：说明"外层沙箱"指运行 agent 的执行器；在 kloop 里默认在
  沙箱内跑测试；改动涉及沙箱或进程集成时，用 `make test` / `make check` 走完整检查（会越界，
  按项目记住），不要给普通 `cargo test` 加越界请求。

### 原则 4：键只看有效果的段，不再记原文

命令键用于生成和匹配 `sandbox_escalate` 规则，以及没有沙箱的平台上的普通门。

- 只读段（`argv_is_readonly`）和 `cd` 不进键，也不参与匹配，门和升级两侧一致。理由：
  kloop 沙箱限制的是写和网络；敏感读取在第 2 层按解析结果硬拦截，对可解析脚本照常生效；
  `cd` 本身没有效果，相对写入目标已经由 `PathFacts` 单独记录。opaque 脚本没有分段，
  不受这条影响。
- `cd <目录>` 永远不生成规则。
- wrapper、第二个词是选项的有效果段，沿用 plan 244 的结论，不生成规则。
- 越界询问删掉逐字记忆，也删掉"本会话所有越界"的会话通配（plan 129/245）：后者等于本会话
  bypass。当初加它是为了审查探针脚本里的联网需求，这部分现在由联网同意覆盖。
- 普通门（没有沙箱的平台）的逐字会话记忆暂不动，不在本计划范围内。

### 原则 5：判定只产出一次（并入 plan 266）

能力同意要求执行层知道用哪一档沙箱。门直接产出
`Verdict { decision, sandbox: Default | WithNetwork | WithWrites(dirs) | Unsandboxed, remember }`，
执行层照单执行，不再自己调用 `sandbox_escalation_remembered` 重新判断。这正是 plan 266
要做的事，阶段 2 以它为载体。

## 六、风险

- 联网同意等于沙箱内可访问整个外网，提示必须写明，不能写成"loopback"。
- 从拒绝证据里取路径不可靠：取不到就不生成写目录授权，宁可多问一次也不猜。
- 按项目记住的完全脱沙箱规则，等于长期信任这个前缀所跑的代码，防不了恶意（用户 2026-11-11：
  防君子不防小人）。对恶意的防线只剩 deny、敏感路径硬拦截和其余命令的沙箱。
- 每个命令前缀第一次越界仍要问一次，这一次省不掉。
- 改参数后，模型的旧习惯可能触发 strict schema 拒收：用工具结果告诉它新写法。
- kloop 在沙箱内跑自测会跳过沙箱测试，改沙箱代码时覆盖面会变小：在 `AGENTS.md` 写明。
- 已经落盘的无用规则（如 `sandbox_escalate(cd … *)`）保留可读，不自动删除。
