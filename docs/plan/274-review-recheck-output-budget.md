## 采样前冻结的协议

- 基线完整保留 plan 273 的 12 次结果：8,192 输出 token、high effort、120 秒硬截止，
  8 次有效、4 次只有推理没有裁决。新实验独立记录，不作为基线失败的重试或替代样本。
- 新组把输出上限翻倍到 16,384；复用原四份冻结问题与证据，每组 3 次，共 12 次。
  模型、提示、证据、high effort、120 秒硬截止、无工具、无历史等设置保持一致，
  仅改变请求体的 `max_output_tokens`。每组内部顺序执行，同时最多两组，不重试、不补样。
- 延续用户已指定的本机 kloop 配置，不修改配置或全局默认值。脚本仅增加显式的
  `--max-output-tokens` 参数，默认仍为 8,192；实际预算进入每次试验的元数据。
- 保持原真值、引用校验和人工验收；不更改候选问题，不依据结果补选片段或追加提示。
  统计交付率、缺陷确认、对照误报、unresolved、token 与耗时；超时和输出截断都记失败。
- 同一 120 秒截止可能成为新限制；先在原速度预算内检验增大输出上限的收益，不同时
  放宽时间预算。若遇到超时，按实记录，不能把它改写成“模型排除了候选”。
- 这是复测已知材料，原留出组本轮也已经公开，不是新留出验证。使用历史基线，未做同期
  随机对照，延迟和 token 波动的因果归属有限；不能据此声称端到端召回提升。

## 真实结果（2026-11-09）

| 组 | 8,192 有效请求 | 16,384 有效请求 | 新组的缺陷确认 / 对照正确排除 | 新组单次中位耗时 |
| --- | ---: | ---: | --- | ---: |
| R1 | 3/3 | 3/3 | C1：3/3；对照：3/3 | 33.3 秒 |
| R4 | 2/3 | 3/3 | C1、C2 各 3/3；对照：3/3 | 58.1 秒 |
| R3 | 0/3 | 1/3 | C1：1/3；对照：1/3；另两次未交付 | 118.1 秒 |
| 原留出组复测 | 3/3 | 3/3 | C1：3/3；对照：3/3 | 36.1 秒 |

分母包含失败请求；中位耗时也包含失败。新组共 10/12 有效（83.3%，基线 66.7%），
没有 JSON、引用校验失败或错误裁决。人工逐条核对全部 23 个已交付判断：13 次正确确认、
10 次正确排除，无误报、错误排除或 unresolved。覆盖 5 个独立缺陷和 4 个独立对照；
开发组 4 个历史漏报在三次试验分别救回 4、3、3 个，不能将三次并集当作单次稳定召回。

R3 的三次结果分别为：

1. 75.723 秒完成，输出 11,169 token，其中推理 10,734。确认普通 `-e` 导致已知 HOME
   被丢弃，正常 home 路径读被过度拒绝，并正确排除无操作数 `bash -c` 的旧行为。
   这次输出确实超过旧上限；单看上限设置，8,192 无法容纳相同输出。
2. 120.012 秒被父进程硬截止，未取得终态响应、裁决或 usage。不能把这次 token 记成零，
   也不能从超时推断它已到达 16,384。
3. 118.076 秒以 `response.incomplete` / `length` 结束，16,384 输出 token 全用于推理，
   没有裁决正文。保持失败，没有延长截止、追加重试或补样。

R3 的确认理由与目标版本代码及后续修复一致。人工验收另核对目标版本的词求值和未知
参数消费方，确认丢失 HOME 会产生未知路径并被拒绝；这些辅助函数未补进本轮冻结请求。
R1、R4 和原留出组的理由也分别追到了错型计数被吞、结构化结束跳过迟到工作检查、
压缩前估算误记上限及无签名完成块回放；负对照均正确识别不受改动影响或前缀仍被保留。

时长合计包含并发请求，不能当作整批墙钟。新组的较低中位数来自部分简单样本更快，
R3 中位反而由 60.2 秒增至 118.1 秒；不能据此说提高上限让请求更快。两批未做同期随机
对照，R4 新组的三次输出也都小于旧上限，因此它由 2/3 到 3/3 的变化不能单独归因于预算。
超时请求的用量未知，新组记录到的 token 较少不代表总消耗下降。

## 结论与取舍

- 提高到 16,384 确实允许部分长推理交付，原来完全不交付的 R3 本轮成功一次；不能继续
  把 8,192 下的失败当成短上下文复核本身无效。但 10/12 仍不足以承诺可靠完成，R3
  依然只有 1/3；继续单纯增加 token 还可能先撞 120 秒截止。
- 保留显式预算参数和原基线，默认仍为 8,192。本轮没有修改全局采样配置、内置 skill
  或共享循环，也没有将复核自动接入 `/code-review`。
- 这轮只解决输出预算的实验问题。人工候选与证据准备成本、自动准备的正确性、证据
  不足时是否正确 unresolved，以及新样本上的端到端召回仍未验证，不据此默认落地。

实际验证包括上述 14 项 Python 回归、12 次真实 API、四组请求与冻结材料一致性、
